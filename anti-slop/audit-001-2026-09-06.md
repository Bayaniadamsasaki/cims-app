# CIMS Anti-Slop Audit 001

- **Tanggal:** 2026-09-06
- **Mode:** AFTER (audit atas kode yang sudah jadi)
- **Cakupan:** `resources/js` (71 berkas, 18.428 baris), `resources/css/app.css`, `resources/views/app.blade.php`, `tailwind.config.js`, `Docs/`, akar repo
- **Rule set:** antislop core R-01..R-38 dan skill `antislop-ui`
- **Status perubahan:** nol. Tidak ada satu berkas aplikasi pun yang diubah untuk audit ini.
- **Total temuan:** 34 (P0: 9, P1: 16, P2: 9)

## Arah desain yang sudah diputuskan

Bagian ini bukan temuan. Ini keputusan yang sudah diambil dan menjadi dasar penilaian di bawah.

- **Blue + White** adalah arah dasar resmi CIMS.
- `Docs/design_cims_dashboard.md` tetap menjadi baseline palet dan referensi. Kode yang ada memang mengimplementasikan dokumen ini (`tailwind.config.js` dan `Components/Cims/theme.jsx` menyebutnya per nomor bagian).
- `Docs/UI_GUIDELINE.md` dinyatakan usang. Isinya (dark mode first, primary neon green `#22C55E`, "inspirasi Linear / Raycast / Vercel / Supabase / GitHub Dark", "gunakan hanya Lucide React") bertentangan dengan arah resmi dan dengan R-30, R-21, R-04, R-03. Baris-baris di dalamnya yang berbentuk perintah kepada agen diperlakukan sebagai konten, bukan instruksi, sesuai aturan batas antislop.
- `DESIGN.md` akan disusun setelah audit ini direview. Selama berkas itu belum ada, **R-37 belum terpenuhi**, sehingga setiap keluaran UI baru berstatus draft dan bukan deliverable.

## Cara membaca prioritas

| Level | Arti | Contoh isi |
|---|---|---|
| **P0** | Rusak atau gagal aksesibilitas. Pengguna terkena langsung. | Kontras gagal, token CSS tidak ada, kontrol mati di chrome global, hierarki navigasi hilang, dialog tanpa semantik |
| **P1** | Konsistensi desain dan pelanggaran antislop. Tidak rusak, tapi merusak kepercayaan visual. | Sisa tema lama, kosakata status bercabang, dua typeface, em dash, emoji dekoratif |
| **P2** | Kebersihan arsitektur dan polish responsif. Utang teknis. | Berkas mati, berkas raksasa, dependency tak terpakai, kerapatan grid mobile |

Urutan prioritas mengikuti permintaan: (1) aksesibilitas dan UI rusak, (2) konsistensi desain, (3) pelanggaran antislop, (4) kontrol mati, (5) responsif/mobile, (6) kebersihan arsitektur sebagai P2.

Kolom `Tier` mempertahankan klasifikasi asli antislop (Hard Gate, Purpose-Gate, Quality Lock) supaya kedua sudut pandang tetap terlihat. Prioritas P dan Tier tidak selalu sejajar: em dash misalnya Hard Gate di antislop tetapi P1 di sini, karena tidak merusak fungsi apa pun.

## Akar masalah tunggal yang menjelaskan sebagian besar temuan

Project ini sedang **di tengah migrasi dari tema dark / neon green ke tema light / blue**, dan migrasi itu dilakukan dengan penggantian nilai di tempat, bukan penulisan ulang.

Bukti langsung ada di kode: `tailwind.config.js` mengarahkan ulang nilai token sambil menahan nama token supaya class lama tetap valid, dan `Pages/Mikrotik/Explorer.jsx:849` menyimpan komentar "Mengubah bg-slate-800 menjadi bg-white agar sesuai light theme".

Lapisan token, komponen dashboard, dan `theme.jsx` menyelesaikan migrasi itu dengan bersih dan berkualitas tinggi. Sisanya menumpuk di tempat yang tidak pernah dilewati: halaman login, scrollbar CSS, halaman explorer, dan berkas mati. Sebagian besar temuan P0 dan P1 di bawah adalah residu tersebut, bukan kesalahan desain baru.

## P0: Rusak dan gagal aksesibilitas (9 temuan)

### 1. Lima belas dari 18 overlay modal tidak punya semantik dialog

- **Lokasi:** 18 overlay `fixed inset-0 z-50` di 13 berkas. Yang **benar** hanya 3: `Hotspot/Packages.jsx:467`, `Hotspot/Vouchers.jsx:1047` dan `:1302`. Sisanya tidak: `Master/Buildings.jsx:178` dan `:255`, `Master/Floors.jsx:226`, `Master/Rooms.jsx:290`, `Master/Categories.jsx:145`, `Master/Vendors.jsx:159`, `Master/FloorDetail.jsx:197`, `Users/Index.jsx:168`, `Maintenance/Index.jsx:232` dan `:331`, ditambah overlay di `Devices/Index.jsx` dan `SpeedtestReports/Partials/`.
- **Rule:** R-24, R-26. **Tier:** Hard Gate.
- **Gejalanya:** tidak ada `role="dialog"`, tidak ada `aria-modal="true"`, tidak ada handler Escape, tidak ada focus trap, dan tidak ada pengembalian fokus setelah modal tutup. Pengguna keyboard bisa Tab keluar dari modal ke halaman di belakangnya yang sedang tertutup scrim, lalu terjebak tanpa cara menutup selain mencari tombol X dengan mata.
- **Kenapa penting:** ini bukan kekurangan yang perlu dibangun dari nol. `Components/Modal.jsx` sudah membungkus `Dialog` dari Headless UI, yang memberi focus trap, Escape, `aria-modal`, dan focus restore secara gratis. Berkas itu dipakai oleh **tepat satu** halaman (`Profile/Partials/DeleteUserForm.jsx`), sementara 13 halaman lain membuat overlay sendiri. Lihat juga temuan 28.

### 2. Link "Forgot password?" hilang saat hover, rasio 1.17:1

- **Lokasi:** `Pages/Auth/Login.jsx:210`, class `hover:text-brand-primaryLight`.
- **Rule:** R-25. **Tier:** Hard Gate.
- **Angkanya:** `brand-primaryLight` bernilai `#DBEAFE` (blue-100) di atas `brand-bg` `#F8FAFC`. Rasio kira-kira **1.17:1** terhadap minimum AA 4.5:1. Keadaan diam link ini aman (`brand-primary` di atas `brand-bg` kira-kira 4.94:1), jadi link hanya menghilang **tepat saat kursor menyentuhnya**.
- **Kenapa penting:** ini satu-satunya kegagalan kontras yang saya klasifikasikan pasti. Penyebabnya residu: `primaryLight` dulu warna hijau pucat di atas panel gelap, di mana pasangan itu masuk akal.

### 3. Sepuluh class di Monitoring/Show.jsx memakai token yang tidak ada

- **Lokasi:** `Pages/Monitoring/Show.jsx`. `text-brand-text` di baris 119, 178, 281, 303, 387, 398, 435, 465. `bg-brand-surface` di baris 132, 220, 396, 443.
- **Rule:** R-24. **Tier:** Hard Gate (UI rusak).
- **Gejalanya:** `tailwind.config.js` mendefinisikan `brand.textPrimary`, `brand.textSecondary`, `brand.textMuted`, `brand.card` dan `brand.cardElevated`, tetapi **tidak** `brand.text` dan **tidak** `brand.surface`. Tailwind tidak menghasilkan CSS untuk class yang tokennya tidak ada, jadi delapan heading kehilangan warna eksplisitnya dan jatuh ke warna warisan induk, sementara empat panel (termasuk `<thead>` tabel riwayat pemindaian dan kotak state kosong chart) dirender tanpa latar sama sekali.
- **Kenapa penting:** halaman ini adalah halaman detail perangkat, yaitu tempat operator melihat satu perangkat yang sedang bermasalah. Kegagalan ini senyap: tidak ada error, hanya hierarki visual yang hilang.

### 4. Search global di header tidak melakukan apa pun

- **Lokasi:** `Components/Cims/DashboardHeader.jsx:47-60`.
- **Rule:** R-26. **Tier:** Hard Gate.
- **Gejalanya:** `<form role="search" onSubmit={(e) => e.preventDefault()}>` tanpa handler apa pun. Input punya `id`, label `sr-only`, placeholder "Cari perangkat, IP, atau lokasi…", dan focus ring yang benar. Semuanya tampak berfungsi. Menekan Enter tidak menghasilkan apa-apa.
- **Kenapa penting:** komponen ini ada di header persisten, jadi kontrol mati ini muncul di **setiap halaman terautentikasi**. Kontrol yang tampak siap dipakai tetapi diam adalah kegagalan kepercayaan yang lebih buruk daripada tidak menampilkan kontrol sama sekali.

### 5. Bel notifikasi tidak punya handler dan tidak punya tujuan

- **Lokasi:** `Components/Cims/DashboardHeader.jsx:75-83`.
- **Rule:** R-26. **Tier:** Hard Gate.
- **Gejalanya:** `<button type="button" className={ICON_BUTTON}>` tanpa `onClick` dan tanpa `Link`. Tombol ini justru menampilkan titik merah jumlah alert belum dibaca dan mengumumkannya ke screen reader lewat `sr-only`, jadi ia secara aktif memberi tahu pengguna ada sesuatu yang perlu dilihat, lalu menolak membukanya.
- **Kenapa penting:** halaman `/alerts` sudah ada dan sudah terdaftar di sidebar. Jarak antara "ada sinyal" dan "tidak ada tujuan" di sini kecil, tetapi efeknya di setiap halaman.

### 6. Hover di sidebar terlihat identik dengan state aktif

- **Lokasi:** `Layouts/AppShell.jsx:121-122`.
  ```js
  const ITEM_ACTIVE = "bg-blue-600 text-white font-semibold shadow-md shadow-blue-500/20";
  const ITEM_IDLE   = "font-medium text-slate-600 hover:bg-blue-600 hover:text-white hover:shadow-md hover:shadow-blue-500/20";
  ```
- **Rule:** R-24, R-33. **Tier:** Hard Gate (hierarki dan state).
- **Gejalanya:** item idle saat dihover menjadi `bg-blue-600` + putih + shadow, yaitu persis definisi `ITEM_ACTIVE`. Selama kursor bergerak menyusuri menu, penanda "Anda sedang di sini" tidak dapat dibedakan dari penanda "kursor sedang di sini". Dua item terlihat aktif bersamaan.
- **Kenapa penting:** ini navigasi utama di shell persisten, jadi berlaku di setiap halaman. Selain itu menyimpang dari speknya sendiri: `Docs/design_cims_dashboard.md` §5B menetapkan state aktif `bg-blue-50` + `text-blue-700`, bukan biru solid.

### 7. Titik status berdenyut terus tanpa pengaman motion-reduce

- **Lokasi:** `Pages/Monitoring/Index.jsx:15` dan `:207`, `Pages/Ruijie/Explorer.jsx:17` dan `:192`, `Pages/Mikrotik/Explorer.jsx:666`, `:671`, `:2025`, `Pages/Topology/Map.jsx:536`.
- **Rule:** R-19, R-35. **Tier:** Hard Gate. **Kriteria:** WCAG 2.2.2 (Pause, Stop, Hide).
- **Gejalanya:** `animate-pulse` dipasang pada titik status `online`, yaitu keadaan **normal**. Di halaman monitoring dengan 30 perangkat sehat, 30 titik berdenyut permanen sekaligus. Tidak ada satu pun yang dijaga `motion-reduce:animate-none`, padahal `AppShell` sudah konsisten memakai `motion-reduce:transition-none` untuk transisinya sendiri.
- **Kenapa penting:** animasi ini mulai otomatis, berlangsung lebih dari 5 detik, tanpa mekanisme jeda. Bacaan paling ketat WCAG 2.2.2 menjadikannya kegagalan; bacaan paling longgar tetap menjadikannya kebisingan visual di layar yang ditatap operator berjam-jam. Denyut juga memberi arti yang salah: denyut biasanya menandai "perhatikan ini", padahal di sini menandai "semuanya beres".

### 8. Scrollbar kustom masih bertema gelap dan hijau di atas halaman putih

- **Lokasi:** `resources/css/app.css:39-49`. Dipakai di `Pages/Mikrotik/Explorer.jsx:761` dan `Layouts/AuthenticatedLayout.jsx:183`.
- **Rule:** R-21, R-24. **Tier:** Hard Gate (residu tema yang merusak).
- **Gejalanya:** track `rgba(15, 23, 42, 0.6)` yaitu slate-900 60%, dan thumb `rgba(16, 185, 129, 0.3)` yaitu emerald-500 30%. Di atas panel putih, track menjadi batang abu gelap yang lebih menonjol daripada thumb-nya sendiri, sementara thumb hijau 30% hampir tak terlihat. Jadi kontrol scroll-nya justru menjadi bagian yang paling sulit dilihat.
- **Kenapa penting:** ini juga satu-satunya tempat emerald masih masuk ke chrome, bukan ke status.

### 9. Tombol tutup di modal tidak punya nama aksesibel dan tidak punya focus ring

- **Lokasi:** contoh `Pages/Master/Buildings.jsx:184-191`. Pola yang sama terulang di semua modal hand-rolled dari temuan 1.
- **Rule:** R-25, R-33. **Tier:** Hard Gate.
- **Gejalanya:** `<button onClick={...}>` yang isinya hanya `<svg>`. Tidak ada teks `sr-only`, tidak ada `aria-label`, tidak ada `type="button"`, dan class-nya hanya punya `hover:`, tanpa `focus:` atau `focus-visible:`. Screen reader mengumumkannya sebagai tombol tanpa nama; pengguna keyboard tidak melihat di mana fokus berada.
- **Kenapa penting:** kontrasnya tajam dengan komponen Cims, yang di tempat lain selalu memasangkan `sr-only` dan `focus-visible:ring-2`. Standarnya sudah ada di project ini, hanya tidak diterapkan di modal buatan sendiri.

## P1: Konsistensi desain dan pelanggaran antislop (16 temuan)

### 10. Kosakata status bercabang tiga, padahal itu elemen identitas inti CIMS

- **Lokasi:** `Components/Cims/theme.jsx` (kanonik), `Pages/Monitoring/Index.jsx:14-21` (`MONITORING_STATUS`), `Pages/Ruijie/Explorer.jsx:13-45` (`STATUS_STYLE`).
- **Rule:** R-06, R-13. **Tier:** Quality Lock.
- **Divergensinya:**

  | | `theme.jsx` | `Monitoring/Index.jsx` | `Ruijie/Explorer.jsx` |
  |---|---|---|---|
  | Label online | sentence case | `"Online"` | `"ONLINE"` |
  | Titik online | shade 500 | `bg-emerald-500 animate-pulse` | `bg-emerald-400 animate-pulse` |
  | Konstruksi chip | tint solid `-50` + teks `-700` | tint solid `-50` + teks `-700` | alpha `-500/10` + border `-500/30` |
  | Kunci `offline` | ada | tidak ada | ada |

- **Kenapa penting:** ini temuan konsistensi paling serius dalam audit. `theme.jsx` adalah satu-satunya yang membawa perbaikan kontras AA yang terdokumentasi (teks badge dinaikkan dari shade 600 ke 700 karena 600 di atas 50 hanya mencapai 3.6:1 dan 3.1:1). Cabang `Ruijie` memakai idiom alpha `/10` dan `/30`, yang khas tema gelap dan tidak pernah dinilai ulang untuk latar putih. Domain yang sama, satu konsep, tiga implementasi berbeda. Kalau nanti kosakata status dijadikan motif identitas CIMS, percabangan ini harus dibereskan lebih dulu.

### 11. Alur autentikasi terbelah dua bahasa visual

- **Lokasi:** `Pages/Auth/Login.jsx` (245 baris, tanpa layout apa pun) vs `Register.jsx`, `ForgotPassword.jsx`, `ResetPassword.jsx`, `ConfirmPassword.jsx`, `VerifyEmail.jsx` (semuanya memakai `Layouts/GuestLayout.jsx`, 18 baris).
- **Rule:** R-06, R-13. **Tier:** Quality Lock.
- **Kenapa penting:** Login adalah halaman pertama yang dilihat pengguna dan satu-satunya yang tidak ikut sistem. Klik "Forgot password?" dari Login memindahkan pengguna ke bahasa visual yang berbeda di dalam satu alur yang sama. Semua temuan 12 sampai 16 juga berada di berkas ini, karena berkas ini yang tidak pernah ikut migrasi.

### 12. Gradient biru ke emerald di panel branding Login

- **Lokasi:** `Pages/Auth/Login.jsx:30`, `bg-gradient-to-br from-brand-primary/20 via-brand-bg to-emerald-900/30`.
- **Rule:** R-01. **Tier:** Hard Gate.
- **Kenapa penting:** dua pelanggaran sekaligus. Pertama, gradient dua-warna sebagai latar penuh adalah pola AI paling dikenali. Kedua, ia menarik emerald, yang di seluruh sistem ini **dikhususkan untuk status**, masuk ke chrome brand. Begitu hijau boleh muncul sebagai dekorasi, hijau kehilangan artinya sebagai "online".

### 13. Overlay grid 60px yang tidak terlihat sama sekali

- **Lokasi:** `Pages/Auth/Login.jsx:33-42`, dua `linear-gradient` garis putih pada `opacity-[0.04]` dengan `backgroundSize: '60px 60px'`.
- **Rule:** R-07. **Tier:** Hard Gate.
- **Kenapa penting:** garisnya putih dan latarnya sudah nyaris putih, jadi pada opacity 4% dekorasi ini tidak menghasilkan apa pun yang bisa dilihat. Ini bukan sekadar pola slop, ini pola slop yang **mati**: kode yang hanya menambah beban render dan beban baca tanpa efek visual. Dulu ia bekerja karena latarnya `#0B0F0D`.

### 14. Dua orb blur berdenyut tanpa henti

- **Lokasi:** `Pages/Auth/Login.jsx:45-46`, `blur-[100px]` dan `blur-[120px]`, keduanya `animate-pulse`, salah satunya `animationDelay: '1s'`.
- **Rule:** R-19. **Tier:** Hard Gate.
- **Kenapa penting:** gerak tanpa pemicu dan tanpa akhir, murni dekoratif, dan salah satunya `bg-emerald-600/8` sehingga menambah masalah temuan 12. Tidak ada pengaman `motion-reduce`.

### 15. Logo mark memakai kontras yang dirancang untuk primary lama

- **Lokasi:** `Pages/Auth/Login.jsx:54`, `text-slate-900` di atas `bg-brand-primary`.
- **Rule:** R-25 (lolos), R-21 (residu). **Tier:** Purpose-Gate.
- **Angkanya:** kira-kira **3.46:1**. Sebagai elemen grafis non-teks, ambangnya 3:1, jadi **ini lolos** dan bukan pelanggaran WCAG. Saya mencantumkannya supaya tidak salah diperbaiki sebagai kegagalan kontras.
- **Kenapa penting:** slate-900 di atas biru-600 terbaca keruh. Pasangan ini dipilih ketika primary masih hijau muda, di mana teks gelap adalah pilihan yang benar. Di atas biru-600, putih yang benar.

### 16. Emoji sebagai ikon fitur di Login

- **Lokasi:** `Pages/Auth/Login.jsx:75-79`, `{ icon: '📡' }`, `{ icon: '🖥️' }`, `{ icon: '🔧' }`.
- **Rule:** R-04. **Tier:** Hard Gate.
- **Kenapa penting:** project ini punya set ikon SVG outline buatan sendiri di `Components/Cims/icons.jsx` yang sudah memuat `IconWifi`, `IconRouter`, dan `IconMaintenance`. Emoji di sini bukan kekurangan aset, hanya jalan pintas yang tidak pernah dirapikan. Emoji juga dirender berbeda di tiap OS, jadi tampilan Login berubah antar perangkat.

### 17. Dua typeface dikirim bersamaan, satu lagi dideklarasikan tapi tidak pernah dimuat

- **Lokasi:** `resources/views/app.blade.php:11` memuat `figtree:400,500,600|inter:400,500,600,700`; baris 19 memasang `class="font-sans"` yang di `tailwind.config.js` resolve ke Figtree; `Layouts/AppShell.jsx` memaksa `font-inter`.
- **Rule:** R-06. **Tier:** Quality Lock.
- **Akibatnya:** halaman auth dirender dengan Figtree, seluruh aplikasi dirender dengan Inter. Pengguna melewati pergantian typeface tepat pada saat login. Selain itu `Plus Jakarta Sans` terdaftar di stack `fontFamily.inter` tetapi tidak pernah dimuat dari mana pun, jadi ia fallback fantom yang tidak akan pernah aktif.
- **Kenapa penting:** dua typeface untuk satu produk perlu alasan yang ditulis. Di sini tidak ada alasannya, ini hanya sisa Breeze (Figtree) yang bertemu pilihan baru (Inter). Berat unduhan font juga ganda.

### 18. `bg-slate-900` sudah menjadi warna primary kedua secara de facto

- **Lokasi:** `Components/Cims/DashboardHeader.jsx:69` (tombol Export Report), `Pages/Hotspot/Vouchers.jsx:440`, `Pages/Hotspot/Vouchers.jsx:961`.
- **Rule:** R-05, R-13. **Tier:** Purpose-Gate.
- **Kenapa penting:** `design_cims_dashboard.md` memang meminta tombol export "hitam/biru gelap", jadi pemakaian di header sesuai spek. Masalahnya penyebarannya: begitu warna itu juga dipakai untuk aksi primer di halaman Vouchers, sistem punya dua warna aksi utama yang bersaing (`blue-600` dan `slate-900`) tanpa aturan kapan memakai yang mana. Mata pengguna kehilangan satu titik jangkar per halaman.

### 19. Em dash di teks UI: 174 kemunculan di 26 berkas

- **Lokasi:** terparah `Pages/Hotspot/Packages.jsx` (42), `Pages/Hotspot/Vouchers.jsx` (35), `Pages/Mikrotik/Explorer.jsx` (17), `Pages/Ruijie/Explorer.jsx` (13), `Pages/Monitoring/Show.jsx` (11), `Pages/Monitoring/Index.jsx` (10), `Pages/Topology/Map.jsx` (10).
- **Rule:** R-02. **Tier:** Hard Gate.
- **Kenapa penting:** R-02 mengecualikan dokumentasi antislop sendiri, bukan string produk. Perlu dicatat bahwa sebagian kemunculan ada di **komentar kode**, bukan teks yang dirender, dan komentar-komentar itu justru komentar berkualitas tinggi (lihat bagian "Yang harus dipertahankan"). Jadi pekerjaan perbaikannya harus memisahkan string UI dari komentar, bukan sapu rata satu regex. Angka 174 adalah batas atas, bukan jumlah pelanggaran yang tampil di layar.

### 20. Emoji sebagai dekorasi: 80 kemunculan di 7 berkas

- **Lokasi:** `Pages/Topology/Map.jsx` (29), `Pages/Mikrotik/Explorer.jsx` (18), `Pages/Alerts/Index.jsx` (12), `Pages/Ruijie/Explorer.jsx` (12), `Pages/Devices/Index.jsx` (5), `Pages/Auth/Login.jsx` (3), `Pages/Monitoring/Index.jsx` (1).
- **Rule:** R-04. **Tier:** Hard Gate.
- **Kenapa penting:** `Mikrotik/Explorer.jsx` memakai emoji sebagai **seluruh set ikon tab**-nya, dan `Alerts/Index.jsx` memakai emoji untuk tingkat keparahan alert termasuk state kosong. Di aplikasi monitoring, ikon severity adalah informasi operasional, bukan hiasan, dan emoji membuatnya bergantung pada font emoji OS. `Devices/Index.jsx` bahkan menaruh emoji di dalam label tombol ("⚡ Sinkronkan Port & Interface").

### 21. Progress bar Inertia berwarna abu, tidak terkait brand

- **Lokasi:** `resources/js/app.jsx:74-75`, `progress: { color: '#4B5563' }`.
- **Rule:** R-05. **Tier:** Quality Lock.
- **Kenapa penting:** indikator navigasi adalah satu-satunya umpan balik yang muncul di setiap perpindahan halaman. Warna gray-600 tidak ada dalam palet CIMS mana pun, dan pada latar putih ia terbaca seperti error bar netral, bukan tanda "sedang memuat".

### 22. Idiom modal bercabang dua, kekuatan blur bercabang dua

- **Lokasi:** varian **tengah** `items-center justify-center p-4` di 8 modal `Master/*` dan `Users/Index.jsx`; varian **bottom sheet** `items-end justify-center ... sm:items-center sm:p-4` di `Hotspot/Packages.jsx:467`, `Hotspot/Vouchers.jsx:1047` dan `:1302`. Blur: `backdrop-blur-md` di 13 tempat, `backdrop-blur-sm` di `Maintenance/Index.jsx:232` dan `:331`.
- **Rule:** R-06, R-10, R-13. **Tier:** Quality Lock.
- **Kenapa penting:** varian bottom sheet justru pola mobile yang lebih baik, dan itu berada di halaman yang sama yang juga punya semantik dialog benar (temuan 1). Jadi project ini sudah punya versi yang benar; ia hanya belum menjadi standar. Sementara itu varian tengah dengan `p-4` di layar 360px menyisakan form yang sempit dan tinggi.

### 23. Residu hijau dan gelap masih terlihat di UI live Mikrotik dan Ruijie

- **Lokasi:** `Pages/Mikrotik/Explorer.jsx:698` (`hover:border-emerald-500/50`), `:2494` dan `:2590` (`bg-red-950/10` untuk baris disabled), `Pages/Ruijie/Explorer.jsx:13-45` (chip alpha `/10` dan `/30`, titik shade `-400`).
- **Rule:** R-21. **Tier:** Purpose-Gate.
- **Kenapa penting:** `red-950` pada 10% di atas putih hampir tidak berbeda dari putih, jadi penanda "baris ini disabled" praktis tidak tersampaikan; ia mengandalkan `opacity-45` yang menyertainya. Border emerald pada hover adalah satu-satunya sisa hijau di chrome interaktif. Dua halaman explorer ini adalah halaman terbesar di project dan paling sedikit tersentuh migrasi.

### 24. PrimaryButton uppercase dengan tracking lebar, sendirian

## Yang harus dipertahankan

Daftar ini sama pentingnya dengan daftar temuan. Kalau fase perbaikan nanti menyapu rata, hal-hal berikut yang paling berisiko rusak.

- **`Components/Cims/theme.jsx`.** Kosakata status diambil dari hasil pindai nyata, dan perbaikan kontras AA-nya **ditulis alasannya** di komentar. `statusOf` memetakan status asing ke `unknown`, bukan ke `warning`, dengan alasan eksplisit: tanpa data monitoring nyata, sistem tidak boleh mengarang peringatan maupun lampu hijau. Ini R-17, R-25, dan R-38 yang sudah terpenuhi karena niat, bukan kebetulan.
- **Set ikon SVG buatan sendiri** di `Components/Cims/icons.jsx` (97 baris, `currentColor` plus `aria-hidden`). Ini bukan Lucide, dan justru itu yang diminta R-04. Menggantinya dengan library adalah kemunduran.
- **`Components/Cims/StatusBadge.jsx`.** Titik warna selalu didampingi teks, dan titiknya `aria-hidden`. Status tidak pernah bergantung pada warna saja.
- **`Pages/Dashboard.jsx` dan `Components/Cims/DeviceStatusList.jsx`.** Semua angka berasal dari controller dengan fallback `?? 0`, ada komentar eksplisit "Tidak ada mode demo dan tidak ada data contoh", dan state kosongnya jujur ("Belum ada perangkat yang dipantau."). Badge tren menjadi netral ketika tidak ada yang bisa dilaporkan, bukan mengarang delta. Ini menutup seluruh baris "Stat Cards With Invented Numbers" dan "Placeholder Empty States" dari `antislop-ui`.
- **Arsitektur shell persisten.** `AppShell` dipasang sekali di `app.jsx`, `CimsLayout` hanya adapter 35 baris, dan guard `WRAPPED = Symbol.for('cims.layoutWrapped')` mencegah pohon React makin dalam tiap navigasi. Kebijakan prefetch-nya juga terdokumentasi: item `live: true` sengaja tidak di-prefetch karena memanggil API perangkat.
- **Fondasi aksesibilitas di `AppShell`.** `aria-current="page"`, `aria-expanded` pada submenu, Escape menutup drawer, `motion-reduce:transition-none`, `focus-visible:ring-2` di semua target, dan `isCurrent()` dibungkus try/catch untuk rute Ziggy yang belum terdaftar.
- **Penanganan overflow chart** di `Components/Cims/TrafficBarChart.jsx:88-90`: `overflow-x-auto` di luar, `min-w-[600px]` di dalam, dengan komentar yang menjelaskan bahwa label sumbu harus tetap terbaca di layar sempit. Ini cara yang benar dan sudah selesai.
- **`Pages/SpeedtestReports/` sebagai contoh struktur.** Dipecah ke `Partials/` dan `constants.jsx`, berkas terbesar 323 baris. Jadikan ini pola untuk temuan 29.
- **Konvensi komentar.** Komentar di berkas-berkas Cims menjelaskan **kenapa**, bukan apa: kenapa jam diisolasi ke komponen sendiri, kenapa `aria-live="off"` pada jam berjalan, kenapa kolom chart butuh `min-w-0`, kenapa scroll harus direset manual. Ini yang diminta `antislop-code`, dan sudah ada di sini. Jangan dibersihkan bersama em dash pada temuan 19.
